# TeamSync — 화면 · 뷰 · 차트 설계

- Feature: `team-scheduler`
- 전제: [데이터 모델](./team-scheduler-data-model.md) §5의 `schedules_in_range` 단일 질의를 모든 뷰가 공유한다

## 1. 화면 골격

세 영역으로 고정한다. 뷰를 바꿔도 좌측 사이드바와 우측 상세 패널의 위치·동작은 변하지 않는다.

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ TeamSync   [프로젝트 ▾]        ‹ 2026년 9월 ›   [오늘]      🔍  🔔  (아바타) │
├────────────┬─────────────────────────────────────────────┬───────────────────┤
│            │  월 │ 주 │ 일 │ 타임라인 │ 마일스톤          │  일정 상세        │
│ ▾ 프로젝트 │ ───────────────────────────────────────────  │ ───────────────── │
│   · 전체   │                                             │ 제목              │
│   · 2026Q4 │                                             │ [디자인 시스템…]  │
│   · 리브랜딩│              (활성 뷰 캔버스)               │                   │
│            │                                             │ 기간              │
│ ▾ 팀       │                                             │ 09.14 → 10.03     │
│   ☑ 개발   │                                             │ 담당 (아바타)     │
│   ☑ 디자인 │                                             │ 진행률 ▓▓▓░ 62%   │
│   ☐ 기획   │                                             │ 상태 [진행중 ▾]   │
│            │                                             │ ─────────────     │
│ ▾ 담당자   │                                             │ 댓글 (3)          │
│   ☑ 전해룡 │                                             │                   │
│   ☐ …      │                                             │ [저장]   [삭제]   │
├────────────┴─────────────────────────────────────────────┴───────────────────┤
│ 상태: 진행 12 · 지연 3 · 이번 주 마감 5                    [+ 일정 추가]     │
└──────────────────────────────────────────────────────────────────────────────┘
```

- **좌측 사이드바** — 프로젝트 선택 + 팀/담당자 필터. 체크박스 상태는 URL 쿼리에 직렬화되어 뷰 전환·새로고침·링크 공유에도 유지된다.
- **중앙 캔버스** — 5개 뷰. 탭만 바뀌고 로드된 데이터는 재사용한다(같은 범위면 재질의 없음).
- **우측 상세 패널** — 어느 뷰에서든 일정 클릭 시 슬라이드인. 인라인 편집이며 화면 이동이 없다. `Esc`로 닫힘.

### URL 구조

```
/w/[workspace]/p/[project]?view=timeline&anchor=2026-09-28&scale=week&teams=dev,design&sel=<scheduleId>
```

뷰 상태 전체가 URL에 담기므로 "지금 내가 보는 화면"을 그대로 링크로 공유할 수 있다. `sel`이 있으면 상세 패널이 열린 채로 복원된다.

## 2. 뷰별 설계

### 2.1 월 뷰 (Month)

- 7×5~6 그리드. 각 셀은 그날 시작·경과하는 일정을 **가로 막대**로 쌓는다.
- 여러 날에 걸친 일정은 주 경계에서 끊어 이어 그리고, 끊긴 쪽 끝에 `◀ ▶` 표시를 둔다.
- 셀 높이 초과 시 `+3개 더` — 클릭하면 그날의 일 뷰로 이동.
- 색은 **팀 색**(`teams.color`)이 기본. 상태가 `blocked`면 좌측에 4px 경고 스트라이프, `done`이면 채도 40% 감소 + 취소선.

**레이아웃 규칙 — 레인 배정**: 여러 날 일정이 같은 주에서 겹칠 때, 같은 일정은 그 주 내내 동일한 세로 위치(레인)를 유지해야 시선이 끊기지 않는다.

```ts
// packages/schedule-core/layout/month.ts
export function assignLanes(bars: WeekBar[]): LaneBar[] {
  const lanes: WeekBar[][] = [];
  // 시작이 이른 순 → 긴 순. 긴 일정이 위쪽 안정적인 레인을 차지한다
  for (const bar of sortBy(bars, [b => b.startCol, b => -b.span])) {
    let lane = lanes.findIndex(l => l.every(b => b.endCol < bar.startCol || b.startCol > bar.endCol));
    if (lane === -1) { lanes.push([]); lane = lanes.length - 1; }
    lanes[lane].push(bar);
  }
  return lanes.flatMap((l, i) => l.map(b => ({ ...b, lane: i })));
}
```

### 2.2 주 뷰 (Week)

- 상단에 **종일 영역**(`all_day = true` 또는 24시간 초과 일정), 하단에 시간 그리드(0~24시, 기본 08~20시 스크롤).
- 같은 시간대 겹침은 열 분할. N개 겹치면 각 폭 `1/N`, 좌측으로 10% 오프셋 계단 배치.
- 현재 시각에 붉은 수평선(`now indicator`), 1분 단위 갱신.
- 빈 영역 드래그 → 그 구간으로 일정 생성 패널 열림.

### 2.3 일 뷰 (Day)

- 주 뷰와 동일한 시간 그리드, 1열. 대신 **담당자별 열 분할 모드**를 토글로 제공한다 — 그날 누가 무엇에 붙어 있는지 보는 용도.
- 일정 바에 제목 + 진행률 + 담당 아바타까지 전부 표시할 폭이 확보된다.

### 2.4 타임라인 뷰 (Timeline / 간트) — 핵심 뷰

장기·중기·단기를 **한 화면에 계층으로** 보여주는 곳이다.

```
                     2026                                    2027
       ┌── Q3 ──┬────── Q4 ──────┬── Q1 ──┬── Q2 ──┐
       │  8   9 │ 10   11   12   │  1   2 │  3   4 │
───────┼────────┼────────────────┼────────┼────────┤
장기   │        │                │        │        │
 리브랜딩       ▐███████████████████████████▌      │      ← horizon: long
───────┼────────┼────────────────┼────────┼────────┤
중기   │        │                │        │        │
 ├ 디자인시스템 ▐██████▌ 62%     │        │        │      ← horizon: mid
 └ 웹 리뉴얼    │       ▐████████████▌     │        │
───────┼────────┼────────────────┼────────┼────────┤
단기   │        │                │        │        │
 ├ 토큰 정의    ▐█▌──┐           │        │        │      ← horizon: short
 └ 컴포넌트 1차 │    └▶▐██▌      │        │        │      ← 의존성 화살표
───────┴────────┴──────┼─────────┴────────┴────────┘
                       ▲ 오늘        ◆ 베타 오픈 (마일스톤)
```

**구성**

| 요소 | 설계 |
|---|---|
| 좌측 고정 열 | 일정 트리 (부모-자식 `parent_id` 들여쓰기, 접기/펼치기). 가로 스크롤 시 고정 |
| 행 그룹 | `horizon` 기준 3개 섹션(장기/중기/단기). 섹션 헤더는 sticky, 접을 수 있음 |
| 시간축 스케일 | `일 / 주 / 월 / 분기` 4단계. 축은 2단(상: 연·분기, 하: 월·주) |
| 바 | 폭 = 기간, 내부 채움 = `progress`. 라벨은 폭이 80px 이상일 때만 렌더 |
| 의존성 | `finish_to_start`는 꺾인 화살표. 순환은 서버에서 삽입 시 거부 |
| 마일스톤 | 다이아몬드 마커 + 전체 높이 수직 점선. 지난 `upcoming`은 붉게 |
| 오늘 | 굵은 수직선, 항상 최상위 z-index |
| 상호작용 | 바 드래그 = 이동, 양끝 핸들 = 리사이즈, 좌측 트리 드래그 = 순서 변경(`sort_order`) |

**스케일 ↔ horizon 연동**: 스케일을 `분기`로 넓히면 단기 섹션은 자동으로 접힌다(수백 개 바가 1px씩 찍히는 것을 막는다). 스케일 `일`에서는 장기 섹션이 접힌다. 사용자가 수동으로 펼치면 그 선택이 우선한다.

**좌표 계산** — 픽셀 변환은 순수 함수 하나로 모은다. 모든 뷰가 이것만 쓴다.

```ts
// packages/schedule-core/layout/timeline.ts
export function createScale(opts: { from: Date; to: Date; pxPerDay: number }) {
  const { from, pxPerDay } = opts;
  return {
    x: (d: Date) => differenceInMinutes(d, from) / 1440 * pxPerDay,
    date: (px: number) => addMinutes(from, px / pxPerDay * 1440),
    // 드래그 종료 시 스케일에 맞춰 스냅: 일 스케일→1시간, 그 외→1일
    snap: (d: Date) => (pxPerDay >= 48 ? roundToNearestHours(d) : startOfDay(d)),
  };
}
```

**가상화**: 세로는 행 윈도잉(보이는 행 ±10개만 DOM), 가로는 보이는 기간 ±1화면 폭의 바만 생성. 1,000건 기준 실제 DOM 노드 200개 미만을 목표로 한다.

### 2.5 마일스톤 뷰

- 프로젝트별 수평 트랙에 마일스톤을 시간순으로 배치한 요약 뷰.
- 각 마일스톤에 **연결된 일정의 진행률 가중 평균**을 도넛으로 표시하여 달성 가능성을 보여준다.
- `due_on`이 지났고 `status = 'upcoming'`이면 지연 배지 + 며칠 지연인지 표기.

## 3. 일정 생성 — 5초 목표

두 경로만 둔다.

1. **캔버스 드래그** — 월/주/일/타임라인의 빈 영역을 드래그하면 그 구간이 기간으로 채워진 퀵 입력 팝오버가 뜬다. 제목만 치고 `Enter`.
2. **퀵 입력 바** — `Cmd/Ctrl + K` → 자연어 한 줄 파싱.

```
"디자인 리뷰 10/3 14시~16시 @전해룡 #디자인"
  → title: 디자인 리뷰, start: 2026-10-03T14:00, end: 16:00,
    assignee: 전해룡, team: 디자인
```

파서는 `packages/schedule-core/parse.ts`의 순수 함수로, 인식 실패한 토큰은 제목에 그대로 남긴다(조용히 버리지 않는다). 해석 결과는 확정 전에 팝오버에 칩으로 보여주고 수정할 수 있게 한다.

나머지 필드(설명, 진행률, 의존성)는 생성 후 상세 패널에서 채운다. 생성 폼에는 두지 않는다.

## 4. 상세 패널

| 섹션 | 편집 방식 |
|---|---|
| 제목 | 인라인 텍스트, blur 시 저장 |
| 기간 | 날짜 피커 2개 + 종일 토글. 변경 시 `horizon` 재추론 후 "장기로 바뀝니다" 안내 |
| horizon | 수동 선택 시 `horizon_locked = true` |
| 담당자 | 멤버 멀티셀렉트 |
| 팀 · 프로젝트 | 단일 셀렉트 (팀 변경 = 색 변경) |
| 상태 · 진행률 | 상태 셀렉트 + 슬라이더. `done` 선택 시 진행률 100% 자동 |
| 상위 일정 | 검색 셀렉트 (자기 자신·자손 제외) |
| 의존성 | 선행/후행 목록 추가·삭제 |
| 댓글 | 스레드 없는 단순 시간순 목록 |

**저장 정책**: 필드 단위 즉시 저장(디바운스 600ms), `updated_at` 낙관적 락. 충돌 시 패널 상단에 "다른 멤버가 수정했습니다 — [내 변경 유지] [불러오기]" 배너를 띄운다.

## 5. 상태 관리

```
URL (뷰·범위·필터·선택)     ← 단일 진실 공급원, 공유 가능
  └ React Query 캐시        ← key: [ws, range, filters]
      └ Realtime 패치 적용  ← 현재 범위와 겹치는 변경만 반영
          └ 낙관적 업데이트 ← 드래그/리사이즈 즉시 반영, 실패 시 롤백
```

전역 스토어를 따로 두지 않는다. 서버 상태는 React Query, 화면 상태는 URL로 충분하다.

## 6. 디자인 토큰

기존 `packages/ui`의 Pretendard 폰트와 라이트/다크 토큰을 재사용한다. 스케줄러 전용으로 추가하는 것:

```scss
// 팀 색 팔레트 — 라이트/다크 모두에서 흰 글자 대비 4.5:1 이상
$team-palette: (#5B8DEF, #E8814A, #3FA372, #A96AD1, #D6455E, #2E9BB5, #8A8F98);

// horizon 섹션 배경 (장기는 가장 옅게 — 배경으로 물러나야 한다)
--horizon-long-bg:  var(--surface-raised);
--horizon-mid-bg:   var(--surface);
--horizon-short-bg: var(--surface-sunken);

--gantt-row-h: 36px;        // 바 높이 24px + 상하 여백 6px
--gantt-tree-w: 280px;      // 좌측 고정 열
--gantt-px-per-day: (day: 96, week: 24, month: 8, quarter: 3);
```

## 7. 접근성

- 캔버스는 키보드만으로 조작 가능: `↑↓` 행 이동, `←→` 기간 이동(스냅 단위), `Enter` 상세 열기, `Shift+←→` 리사이즈.
- 색만으로 상태를 전달하지 않는다 — `blocked`는 스트라이프, `done`은 취소선을 함께 쓴다.
- 간트 각 바는 `role="button"` + `aria-label="디자인 시스템, 9월 14일부터 10월 3일까지, 진행률 62%, 담당 전해룡"`.
- 마일스톤 수직선은 장식이므로 `aria-hidden`, 대신 마커에 라벨을 둔다.
