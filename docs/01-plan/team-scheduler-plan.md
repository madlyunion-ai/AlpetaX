# TeamSync — 팀 일정 스케줄러 · Plan

- Feature: `team-scheduler`
- 작성일: 2026-09-28
- 스택: Next.js(App Router) + Supabase(Postgres/Auth/Realtime/Storage)
- 레벨: Dynamic (SaaS 멀티테넌시)

## 1. 문제 정의

Monday.com / Asana는 팀이 "일정을 공유하고 진행 상황을 한눈에 본다"는 목적에 비해 과도하게 복잡하다.
설정 항목이 많고 학습 곡선이 길어, 10~30인 규모 팀은 결국 스프레드시트로 회귀한다.

**우리가 푸는 문제**: 일정 입력은 5초 안에, 확인은 한 화면에서.

## 2. 제품 원칙 (Non-Goals 포함)

| 원칙 | 의미 |
|---|---|
| 입력은 최소 | 필수 입력은 `제목 + 기간` 둘뿐. 나머지는 전부 선택 |
| 하나의 데이터, 다섯 개의 뷰 | 월/주/일 + 타임라인(간트) + 마일스톤이 같은 데이터를 다르게 그린다 |
| 상세는 항상 곁에 | 어느 뷰에서든 클릭 → 우측 패널에서 상세 보기/편집. 화면 이동 없음 |
| 팀이 단위 | 개인 투두가 아니라 "누가 언제 무엇을" 팀 전체가 본다 |

**하지 않는 것 (Non-Goals)**
- 자동화 규칙 빌더, 커스텀 필드 빌더, 폼/앱 마켓플레이스
- 칸반 워크플로 커스터마이징, 시간 추적(타임시트), 리소스 원가 관리
- 문서 협업(위키), 채팅 (Slack 알림 연동으로 대체)

## 3. 사용자 및 권한

| 역할 | 권한 |
|---|---|
| Owner | 워크스페이스 결제·삭제, 전체 권한 |
| Admin | 멤버 초대/제거, 팀·프로젝트 생성 |
| Member | 자신이 속한 팀의 일정 생성/편집, 타 팀 일정 읽기 |
| Guest | 초대된 프로젝트만 읽기 (외부 협력사용) |

## 4. 핵심 개념 (도메인 용어)

- **Workspace** — 과금·테넌시 경계. 회사 하나 = 워크스페이스 하나
- **Team** — 워크스페이스 내 조직 단위 (예: 개발팀, 디자인팀)
- **Project** — 일정들의 묶음. 장기 목표 하나에 대응
- **Schedule** — 일정 1건. 기간(`start_at`~`end_at`), 담당자, 진행률을 가짐
- **Milestone** — 날짜 하나로 표현되는 기준점. 달성/미달성 상태만 가짐
- **Horizon** — 일정의 시계(視界). `long`(장기, 분기~년) / `mid`(중기, 월~분기) / `short`(단기, 주 이하). 기간 길이로 자동 추정하되 사용자가 덮어쓸 수 있음
- **Dependency** — 일정 간 선후 관계 (`A 종료 → B 시작`). 타임라인에서 화살표로 표시

## 5. 사용자 스토리 (우선순위 순)

### P0 — 이게 없으면 제품이 아님
1. 멤버로서, 제목과 기간만 입력해 일정을 만들 수 있다.
2. 멤버로서, 월간 캘린더에서 팀 전체 일정을 색상으로 구분해 본다.
3. 멤버로서, 주간·일간 뷰로 전환해 시간대별 일정을 본다.
4. 리드로서, 타임라인(간트) 차트에서 장기/중기/단기 일정이 계층으로 쌓인 모습을 본다.
5. 누구든, 일정을 클릭하면 우측 상세 패널이 열리고 거기서 바로 편집·저장한다.
6. 리드로서, 프로젝트에 마일스톤을 찍고 타임라인 위 수직선으로 확인한다.

### P1 — 팀 협업이 되게 함
7. 관리자로서, 이메일로 멤버를 초대하고 역할을 부여한다.
8. 멤버로서, 담당자/팀/상태로 일정을 필터링한다.
9. 멤버로서, 타임라인에서 바를 드래그해 기간을 옮기거나 끝을 잡아 늘린다.
10. 멤버로서, 다른 사람이 편집하면 새로고침 없이 내 화면이 갱신된다 (Realtime).
11. 멤버로서, 일정에 댓글을 달아 맥락을 남긴다.

### P2 — 쓸 만해짐
12. 반복 일정 (주간 정기회의 등).
13. 마일스톤 지연 시 Slack/이메일 알림.
14. 개인 캘린더(Google/Outlook) 읽기 전용 ICS 구독.
15. 대시보드: 이번 주 마감, 지연 일정, 마일스톤 달성률.

## 6. 성공 기준

| 지표 | 목표 |
|---|---|
| 일정 1건 생성 소요 시간 | 10초 이내 |
| 첫 일정 입력까지 (신규 가입) | 3분 이내 |
| 월간 뷰 초기 렌더 | 1,000건 일정 기준 200ms 이내 |
| 주간 활성 팀 리텐션 (4주) | 40% 이상 |

## 7. 범위 밖 리스크

- **기존 AlpetaX 코드베이스는 Vite SPA**다. 이 기능은 Next.js를 전제하므로 `apps/` 하위 별도 앱으로 분리하거나 신규 저장소로 가는 편이 안전하다. → Design 문서 §1에서 결정.
- Supabase Realtime 동시 편집 충돌 해소 정책 필요 (last-write-wins + `updated_at` 낙관적 락으로 시작).
